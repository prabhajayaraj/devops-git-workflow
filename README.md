# DevOps Git Workflow Project

## Project Overview
This project demonstrates Git and GitHub version control practices used in DevOps workflows.

## Objectives
- Manage source code using Git and GitHub.
- Create and manage main, dev, and feature branches.
- Practice feature development using pull requests.
- Merge feature branches into dev and dev into main.
- Maintain project documentation using Markdown.
- Use Git tags to manage project releases.

## Branching Strategy
- **main:** Stable project version.
- **dev:** Integration branch for development.
- **feature/add-project-details:** Project documentation updates.
- **feature/add-release-process:** Release versioning guidelines.

## Tools Used
- Git
- GitHub
- Visual Studio Code
- PowerShell

## Project Files
- `.gitignore` — Specifies files Git should ignore.
- `project-info.md` — Contains project information.
- `docs/git-workflow.md` — Documents the Git workflow.
- `README.md` — Project overview and instructions.

## Pull Request Workflow
1. Create a feature branch.
2. Make and commit changes.
3. Push the feature branch to GitHub.
4. Create a pull request and merge it into the target branch.
5. Merge `dev` into `main` after integration.

## Release Tags

- `v1.0.1` — Completed Task 4 Git workflow.
